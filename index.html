THE IDEA

Don't just think harder. Look closer.

Many real-world visual questions can't be answered by reasoning over the input alone. You may need to localize dozens of tiny objects, look up a long-tail entity on the web, or compute a 3D distance from depth and camera poses. Spending more reasoning tokens helps only a little: moving GPT-6 Luna from xhigh to max effort more than doubles its spend for +3.0 points.

OpenVLHarness wraps any MLLM with two mechanisms. A capability layer puts perception, search, and code tools behind task-level interfaces and renders their outputs as evidence the model can read. A persistent multimodal memory keeps every image, mask, depth array, and web page addressable by handle, so later steps can inspect it again and compute over it.

Read the full abstract

Multimodal large language models (MLLMs) have made rapid progress on visual reasoning, yet many tasks require evidence that is difficult to obtain through internal reasoning alone: a controlled study on 12 benchmarks shows that simply increasing the inference budget yields only modest gains. Such tasks demand grounded perception, external knowledge, and numerical measurements obtained through heterogeneous tools, whose outputs must be made interpretable to the model and retained across reasoning steps. We introduce OpenVLHarness, a multimodal reasoning harness organized around a capability layer and persistent multimodal memory. The capability layer combines task-level tool interfaces with evidence rendering, providing consistent access to heterogeneous backends and converting their outputs into model-readable observations. Persistent multimodal memory retains the corresponding images, structured data, and web references as addressable artifacts throughout each query. A coding interface executes generated programs over stored data, enabling computations that combine results from multiple tools. Together, these mechanisms support an iterative process of acquiring, inspecting, and composing multimodal evidence. Evaluated on 23 benchmarks across perception, spatial reasoning, visual search, and multimodal question answering, OpenVLHarness consistently surpasses strong MLLM backbones and outperforms existing visual tool-use baselines across six open and proprietary backbones of different scales, improving average performance by 9.2–12.6 points, including +11.2 with Qwen3-VL-8B, +9.2 with Kimi K3, and +11.2 with GPT-6 Sol. In that study, even though OpenVLHarness incurs additional cost from multi-step tool use, giving the base GPT-6 Luna an even larger reasoning budget (1.27× the cost of OpenVLHarness) improves the average only from 49.6 to 51.5, compared with 62.9 for OpenVLHarness.

Task-level tool interfaces

Each capability is defined by what it does: its typed inputs and the evidence it exposes. Backends are wrapped behind it, so Grounding can run on SAM 3 or Grounding DINO, and OCR on PaddleOCR-VL or DeepSeek-OCR, without changing the orchestrator's vocabulary.

Model-facing evidence rendering

An RLE mask is precise but unreadable to a model. Every capability ships an output processor that turns raw results into a labeled overlay, a colorized depth map, or a trajectory plot, plus a concise description and compact structured fields.

Persistent multimodal memory

An artifact registry separates payload from handle. Images (tool_image_6), data bindings (depth_result), and web references (webpage_url_1) persist across turns, and the Python Coding Agent receives them as live variables.

INSIGHTS

What we found

Five takeaways from 23 benchmarks, seven backbones, component ablations, and a failure study of 9,980 trajectories.

INSIGHT 01

Gains hold on every backbone, across all four domains.

OpenVLHarness improves the average of every backbone we tried, from an 8B open model to frontier APIs. With GPT-6 Sol it improves all 23 of 23 benchmarks. The biggest jumps come where the model needs evidence it cannot produce itself: exhaustive counting, box-level grounding, and multimodal search.

INSIGHT 02

Tool access isn't enough. The harness design matters.

Existing visual tool-use harnesses often fall below the no-tool baseline. With GPT-6 Luna, Codex averages 41.5, under the base model's 43.2; OpenVLHarness reaches 55.8. On Qwen2.5-VL-7B, our training-free harness also beats agents that were fine-tuned for tool use.

INSIGHT 03

Evidence and reasoning are complementary.

Raising reasoning effort helps every method, but the base model and Codex flatten out. At max effort they reach 58.3 and 57.4, still below OpenVLHarness at medium effort (62.9), which costs less than half as much. Give the harness more reasoning and it keeps climbing, to 68.6.

INSIGHT 04

Both mechanisms pull their weight.

Starting from the bare model, we add raw tool access, then the capability layer, then memory. Each step adds points. Text-only memory barely helps (+0.7 / +0.3). The jump comes when tool-generated images become reusable handles (+2.2 / +3.4), and it is largest on search and deep research (+6.2 / +3.5).

INSIGHT 05

Diagnose failures, then specialize the right way.

A Kimi K3 critic labeled 9,980 failed Qwen3-VL-8B trajectories (92% agreement with humans). Failures differ by domain: 72% of counting failures are wrong tool outputs in crowded scenes, 49% of search failures are a tool that was never called, and only 2–8% are evidence the model ignored.

The critic's proposed remedies tell you which knob to turn. Where harness text edits dominate, harness search wins. Where new tools dominate, tool generation wins, with no weight updates.
