Task-level tool interfaces

A capability is defined by its operation, typed inputs, and the evidence it exposes. Backends are interchangeable: Visual Grounding runs on SAM 3 or Grounding DINO, OCR on PaddleOCR-VL or DeepSeek-OCR.

Model-facing evidence rendering

An output processor renders each raw result into a model-facing observation: a labeled mask overlay, a colorized depth map, or a trajectory plot, with a concise description and compact structured fields.

Persistent multimodal memory

A per-query artifact registry separates payloads from handles. Images (tool_generated_image_n), data bindings (depth_result), and web references (webpage_url_n) persist across turns; the Python Coding Agent receives bindings as variables.

INSIGHTS

Findings

23 benchmarks, seven backbones, component ablations, and a failure analysis of 9,980 trajectories.

INSIGHT 01

Consistent gains across backbones and domains

Average gains of +9.2 to +12.6 points over the base model across six backbones. With GPT-6 Sol, every one of the 23 benchmarks improves. Gains are largest on counting, grounding, and multimodal search.

INSIGHT 02

Effective tool use depends on the harness

With GPT-6 Luna, Codex (41.5) and Visual Sketchpad (42.8) average below the no-tool baseline (43.2); OpenVLHarness reaches 55.8. On Qwen2.5-VL-7B, OpenVLHarness (35.6) exceeds the training-based baselines without updating model weights.

INSIGHT 03

Evidence acquisition complements reasoning effort

GPT-6 Luna on 12 benchmarks. At max effort, Base and Codex reach 58.3 and 57.4, below OpenVLHarness at medium effort (62.9) at less than half their model-token cost. OpenVLHarness reaches 66.6 at high and 68.6 at max effort.

INSIGHT 04

Both mechanisms contribute

Components are added cumulatively to the no-tool baseline (Qwen3-VL-8B / 32B, overall average): raw tool access +3.8 / +4.3, capability layer +3.4 / +3.2, textual memory +0.7 / +0.3, multimodal memory +2.2 / +3.4. The multimodal-memory step is largest on visual search and deep research (+6.2 / +3.5).

INSIGHT 05

Failure analysis guides specialization

Kimi K3 critiques 9,980 failed Qwen3-VL-8B trajectories (92% agreement with human labels on 100 samples). Primary causes differ by domain: incorrect tool output accounts for 72% of counting and grounding failures, and an omitted tool call for 49% of search failures. Unusable or ignored correct tool outputs account for 2–8%.

Harness search improves ERQA and RealWorldQA (+4.1, +3.7), where harness-text remedies dominate. Tool generation improves SparBench and FREAK-VQA (+8.2, +4.5), where task-specific-tool remedies dominate. Neither updates model weights.
